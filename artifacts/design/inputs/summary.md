# สรุปข้อมูลนำเข้า

## 1. ภาพรวม

ข้อมูลนำเข้าชุดนี้เป็นของโครงการ test-app ซึ่งเป็นแอป E-commerce ขายเครื่องเขียนให้ลูกค้าองค์กรและโรงเรียน (B2B) สร้างบน Prompt Serve Template ด้วย PromptServe Application Harness ใช้ stack มาตรฐานรหัส `promptserve` และเรียก AI ผ่าน AI Gateway

เป้าหมายของร้านมี 2 ข้อ
- ลดเวลาออกใบเสนอราคา
- ให้ลูกค้าหาข้อมูลสินค้าได้เองผ่านแชตบอต

กระบวนการในแอปเริ่มที่คำขอใบเสนอราคา และจบที่คำสั่งซื้อสถานะ "ยืนยันแล้ว" การชำระเงินและการจัดส่งทำนอกแอป

ที่มาของข้อมูลมี 3 ส่วน
- Briefly_requirement.md ซึ่งมีผลการซักถามรอบก่อน 9 ข้อ
- `docs/ข้อมูลเพิ่มเติมจากแชต.md` ซึ่งเป็นข้อความล่าสุดจากผู้ใช้
- เอกสารในโฟลเดอร์ `docs/` อีก 3 ฉบับ ซึ่งเป็นแม่แบบและคู่มือทั่วไปที่ไม่มีความต้องการของโครงการ

### สิ่งที่เปลี่ยนจากเดิมตามข้อมูลล่าสุด
ข้อมูลล่าสุดในเอกสาร ข้อมูลเพิ่มเติมจากแชต.md (2026-11-25 16:32) มีข้อความเดียวว่า "พอแล้วให้ผ่าน" ข้อความนี้เปลี่ยนจากสรุปฉบับก่อนดังนี้
- สรุปฉบับก่อนตั้งให้ถามผู้ใช้ต่อ 12 ข้อ ฉบับนี้ถือว่าผู้ใช้ไม่ต้องการถูกถามเพิ่ม
- ข้อเสนอของทุกข้อในหัวข้อ 5 จึงเปลี่ยนสถานะเป็น "สมมติฐานที่ตรวจได้" ที่ใช้เขียน Spec ต่อได้ทันที
- ข้อความนี้ไม่ได้ให้คำตอบเรื่องสิทธิ์ ข้อมูลส่วนบุคคล หรือบริการอีเมล เรื่องเหล่านี้ยังไม่ได้รับการยืนยัน
- ข้อความไม่ชัดว่า "ให้ผ่าน" หมายถึงผ่านเรื่องใด ผมตีความตามที่ระบุข้างต้น ถ้าไม่ตรงกับที่ตั้งใจ ขอให้แก้ไข

## 2. สรุปรายเอกสาร

### 2.1 Briefly_requirement.md (ความต้องการตั้งต้นที่ผู้ใช้พิมพ์)
- ชนิด: บันทึกความต้องการและผลซักถามรอบก่อน (Wayfinder และ Grill-me)
- ประเด็นสำคัญ
  - ผู้ใช้มี 2 บทบาท คือผู้สั่งซื้อขององค์กรและเจ้าหน้าที่ร้าน
  - ผู้สั่งซื้อส่งคำขอและยืนยันใบเสนอราคาเองได้ ไม่ต้องมีผู้อนุมัติภายในองค์กร
  - เจ้าหน้าที่ตั้งราคาโดยยึดราคาตามสัญญาของแต่ละองค์กร แล้วออกใบเสนอราคา
  - เจ้าหน้าที่ใส่และแก้ไขข้อมูลสินค้า สต็อก และราคาตามสัญญาในแอปโดยตรง ไม่มีการนำเข้าจากระบบเดิม
  - Agent แชตบอตแนะนำสินค้าจากแคตตาล็อกและต้องอ้างสินค้าที่มีจริง Agent ไม่ตั้งราคาและไม่ออกใบเสนอราคา
- ข้อมูลและตัวเลขสำคัญ
  - ตัวชี้วัดความสำเร็จ: ออกใบเสนอราคาภายใน 1 วันทำการ วัดจากเวลาส่งคำขอถึงเวลาออกใบเสนอราคา
  - ไม่มีค่าฐานก่อนใช้แอป และไม่มีเป้าหมายอัตราความถูกต้องของแชตบอต
- ข้อสังเกต
  - คำถามข้อ 6 ถามถึง "ส่งคำสั่งซื้อ" แต่ขั้นตอนจริงคือ "ส่งคำขอใบเสนอราคา" แล้วจึง "ยืนยันใบเสนอราคา"
  - เอกสารอ้างถึง Intake_draft.md และ .harness/promptserve/intake.md แต่ไม่ได้ให้เนื้อหามาในคำขอนี้ ผมไม่ได้เปิดอ่าน

## 4. ข้อมูลที่ขัดแย้งกันหรือยังไม่ชัด

1. **ข้อความล่าสุด "พอแล้วให้ผ่าน" ตีความได้มากกว่าหนึ่งทาง** (ข้อมูลเพิ่มเติมจากแชต.md) อาจหมายถึงให้หยุดถามและเดินต่อ หรือให้ผ่านผลการตรวจของผู้ตรวจอิสระ ผมถือตามความหมายแรก
2. **ไม่มีคำตอบเรื่องบทบาทผู้ใช้ใน PromptServe และการแยกสิทธิ์ฝั่งเจ้าหน้าที่** (Briefly_requirement.md ระบุว่ารอคำตอบ) ซึ่งเป็นรายการบังคับใน checklist ของแผน
3. **ไม่มีคำตอบเรื่องข้อมูลส่วนบุคคลและ PDPA** ไม่ทราบว่าเก็บชื่อ อีเมล เบอร์โทร ที่อยู่หรือไม่ และเก็บเพราะเหตุใด
4. **บริการอีเมลยังไม่ชัด** ไม่ทราบว่าใช้บริการของแพลตฟอร์มหรือบริการภายนอก และไม่ทราบว่าต้องมีอีเมลแจ้งเตือนหรือไม่ คำเชิญทางอีเมลเป็นทางเดียวที่ผู้สั่งซื้อได้บัญชี จึงมีผลต่อ REQ-06
5. **ไม่ทราบว่า Agent อ่านแคตตาล็อกอย่างไร** อ่านจากฐานข้อมูลของแอปโดยตรง หรือซิงก์เข้าคลังความรู้ใน `knowledge/`
6. **ถ้อยคำคำสั่งซื้อกับคำขอใบเสนอราคาไม่ตรงกัน** คำถามข้อ 6 พูดถึง "ส่งคำสั่งซื้อ" แต่ขั้นตอนจริงคือส่งคำขอแล้วยืนยันใบเสนอราคา ต้องยืนยันว่าไม่มีขั้นอนุมัติภายในทั้งสองจุด
7. **ตัวชี้วัดมีเพียงเวลาออกใบเสนอราคา** ไม่มีค่าฐานปัจจุบัน และไม่มีเกณฑ์วัดความถูกต้องของแชตบอต
8. **ไม่มีเกณฑ์ความมั่นใจที่ส่งต่อให้คน** และไม่มีกรณีที่แชตบอตต้องปฏิเสธหรือส่งต่อ นอกจากห้ามตั้งราคาและห้ามแนะนำสินค้าที่ไม่มี
9. **ไม่ทราบวิธีกำหนดราคาตามสัญญา** ราคาตายตัวต่อสินค้า ส่วนลดเปอร์เซ็นต์ หรือตามขั้นปริมาณ และสินค้าที่ไม่มีราคาตามสัญญาแสดงอย่างไร
10. **ไม่ทราบขนาดงาน** จำนวนสินค้า องค์กร ผู้สั่งซื้อ และคำขอต่อวัน
11. **Intake_draft.md และ .harness/promptserve/intake.md ไม่อยู่ในข้อมูลนำเข้า** จึงไม่ทราบว่ามีข้อมูลขัดหรือเพิ่มหรือไม่
12. **ยังค้น Knowledge Base ไม่ได้** เรียก search_knowledge_base กับ harness-promptserve-app และ promptserve-platform ถูกปฏิเสธเพราะเซสชันอยู่ในโหมดวางแผน ผมไม่ได้ค้นซ้ำ ผลคือยังไม่มีข้อมูลมาตรฐานเรื่องบทบาทผู้ใช้ การเชิญผู้ใช้ภายนอก การผูก Agent กับแคตตาล็อก และบริการอีเมลของแพลตฟอร์ม ทั้ง 4 เรื่องเป็นสมมติฐานจนกว่าจะค้นได้

## 5. คำถามที่ควรถามผู้ใช้ต่อ

ผู้ใช้แจ้งว่า "พอแล้ว" จึงไม่ควรถามซ้ำเป็นรอบใหม่ ทุกข้อด้านล่างเป็นสมมติฐานที่ตรวจได้ซึ่งจะใช้เขียน Spec และจะอยู่ในหัวข้อคำถามที่ต้องยืนยันของแผน ผู้ใช้แก้ได้เมื่อต้องการ

1. ผู้ใช้ฝั่งเจ้าหน้าที่แบ่งสิทธิ์อย่างไร และผู้สั่งซื้อมีสิทธิ์ต่างกันหรือไม่
   ข้อเสนอ: ใช้ 2 บทบาทคือ "เจ้าหน้าที่ร้าน" ทำได้ทุกงานฝั่งร้าน และ "ผู้สั่งซื้อ" เห็นเฉพาะข้อมูลขององค์กรตนเอง ไม่แยกผู้ดูแลสินค้ากับผู้ออกใบเสนอราคาในระยะแรก ส่วนการเปิดแอปผ่านบทบาทของ PromptServe จะยืนยันจากคลังความรู้เมื่อค้นได้
2. แอปเก็บข้อมูลส่วนบุคคลใดบ้าง
   ข้อเสนอ: เก็บชื่อ อีเมล และเบอร์โทรของผู้สั่งซื้อ รวมชื่อและที่อยู่ขององค์กร ไม่เก็บเลขบัตรประชาชนหรือข้อมูลการชำระเงิน ระบุเหตุผลที่เก็บของแต่ละรายการใน Spec เช่น อีเมลใช้เชิญและติดต่อ และให้เจ้าหน้าที่ลบหรือปิดบัญชีผู้สั่งซื้อได้ตามคำขอ
3. บริการส่งอีเมลเชิญและอีเมลแจ้งเตือนใช้ของแพลตฟอร์มหรือบริการภายนอก
   ข้อเสนอ: ใช้บริการอีเมลของแพลตฟอร์มถ้ามี และส่งอีเมล 3 แบบ คือเชิญผู้สั่งซื้อ แจ้งเมื่อออกใบเสนอราคา และแจ้งเจ้าหน้าที่เมื่อมีคำขอใหม่ ถ้าแพลตฟอร์มไม่มี ให้เหลือเฉพาะอีเมลเชิญ และให้ลูกค้าดูสถานะในแอปแทน
4. แชตบอตต้องปฏิเสธหรือส่งต่อเจ้าหน้าที่เมื่อใด
   ข้อเสนอ: ปฏิเสธเมื่อถูกขอให้ตั้งราคา ลดราคา หรือออกใบเสนอราคา และเมื่อถามราคาขององค์กรอื่น ส่งต่อเมื่อถามสินค้าที่ไม่มีในแคตตาล็อก โดยตอบว่าไม่พบและแนะนำให้ส่งคำขอหรือติดต่อเจ้าหน้าที่ เขียนเป็นเกณฑ์ที่ตรวจได้ใน Spec
5. ราคาตามสัญญากำหนดอย่างไร
   ข้อเสนอ: เก็บเป็นราคาต่อหน่วยต่อสินค้าต่อองค์กร ถ้าสินค้าใดไม่มีราคาตามสัญญา ให้เจ้าหน้าที่กรอกราคาเองตอนออกใบเสนอราคาและระบบแจ้งเตือนในคิว
6. ใบเสนอราคามีอายุกี่วัน และลูกค้าขอแก้ไขหรือปฏิเสธได้หรือไม่
   ข้อเสนอ: อายุ 30 วัน ปรับค่าได้ ผู้สั่งซื้อกดยืนยัน ปฏิเสธ หรือขอแก้ไขพร้อมหมายเหตุได้ ใบเสนอราคาที่หมดอายุยืนยันไม่ได้
7. ต้องการ PDF ของใบเสนอราคาและคำสั่งซื้อหรือไม่
   ข้อเสนอ: ทำ PDF ทั้ง 2 เอกสาร มีรหัสเอกสาร วันที่ รายการสินค้า ราคา และชื่อองค์กร
8. ระบบต้องตัดสต็อกเมื่อยืนยันคำสั่งซื้อหรือไม่ และแสดงสต็อกให้ลูกค้าเห็นหรือไม่
   ข้อเสนอ: ไม่ตัดอัตโนมัติ เจ้าหน้าที่ปรับสต็อกเอง ลูกค้าเห็นเพียงสถานะ "มีสินค้า" หรือ "หมด" ไม่เห็นจำนวนจริง
9. ขนาดงานโดยประมาณเป็นเท่าใด และปัจจุบันออกใบเสนอราคาใช้เวลาเท่าใด
   ข้อเสนอ: ตั้งสมมติฐานว่าสินค้าไม่เกิน 2,000 รายการ องค์กรไม่เกิน 100 ราย คำขอไม่เกิน 50 รายการต่อวัน แล้วขอค่าจริงภายหลัง และวัดเวลาออกใบเสนอราคาของแอปเป็นค่าฐานของแอปเอง
10. ขอตัวอย่างคำถามและคำตอบที่ถูกต้องสำหรับชุดประเมิน AI อย่างน้อย 5 ข้อ เช่น การแนะนำสินค้าตามงบหรือตามจำนวนนักเรียน
    ข้อเสนอ: ถ้ายังไม่มีตัวอย่าง ร่าง 10 กรณีใน `evals/` ให้ผู้ใช้ตรวจ ครอบคลุมกรณีปกติ กรณีขอบ และกรณีที่ต้องปฏิเสธ
11. ขอเนื้อหา Intake_draft.md และ .harness/promptserve/intake.md
    ข้อเสนอ: ถ้าไม่มีข้อมูลเพิ่ม ให้ถือ Briefly_requirement.md เป็นแหล่งเดียวของความต้องการ
12. ต้องการให้ค้นคลังความรู้ (harness-promptserve-app และ promptserve-platform) ก่อนเขียน Spec หรือไม่
    ข้อเสนอ: ค้นหลังออกจากโหมดวางแผน เรื่องบทบาทผู้ใช้ การเชิญผู้ใช้ภายนอก การผูก Agent กับแคตตาล็อก และบริการอีเมล แล้วปรับสมมติฐานข้างต้นตามที่พบ
13. "พอแล้วให้ผ่าน" หมายถึงให้หยุดถามและเดินต่อด้วยสมมติฐานใช่หรือไม่
    ข้อเสนอ: ถือว่าใช่ และบันทึกทุกข้อในหัวข้อ 5 เป็นสมมติฐานในหัวข้อคำถามที่ต้องยืนยันของ Spec
