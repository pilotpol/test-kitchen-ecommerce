### แนวทางนักวิเคราะห์ระบบใน PromptServe Application Harness
ใส่เนื้อหาต่อไปนี้ภายในหัวข้อที่ role prompt กำหนด
- Intent: ระบุผู้ใช้ตามบทบาทของ PromptServe และตัวชี้วัดความสำเร็จที่วัดได้ (เวลาที่ลดลง อัตราความถูกต้อง)
- Spec: ตาราง "การแยกขั้นตอนแบบ System One และ System Two" หนึ่งแถวต่อขั้นตอน คอลัมน์ ขั้นตอน, ประเภท (move/rule/decide/extract/generate/human), ผู้ทำ (โค้ด, Workflow, System One, System Two, เจ้าหน้าที่), เกณฑ์ความมั่นใจที่ส่งต่อให้คน
- Spec: ระบุ Agent ของแอป คลังความรู้ที่ใช้ เครื่องมือ (MCP) และ guardrail ที่ต้องมี
- Spec และ Design ใช้ tech stack มาตรฐานของ harness เสมอ (Next.js, Go + Gin, PostgreSQL, Agent และคลังความรู้ของแอป) ไม่ถามผู้ใช้เรื่อง stack ระบุตารางฐานข้อมูล, API ของ backend (method, path, input, output), หน้าจอ, คำสั่งของ Agent และรายการเอกสารใน `knowledge/`
- Spec: เกณฑ์ยอมรับของส่วน AI เขียนเป็นพฤติกรรมที่ตรวจได้ ไม่ใช่ข้อความตรงตัว และระบุกรณีที่ต้องปฏิเสธหรือส่งต่อ
- Plan: มีขั้น "เตรียมชุดประเมิน AI ใน `evals/`" อย่างน้อย 10 กรณี ครอบคลุมกรณีปกติ กรณีขอบ และกรณีที่ต้องปฏิเสธ
- Plan: ระบุลำดับ Local Run, Playground และ Go live ระบบนำขึ้นเองเมื่อทุก backlog รวมเข้างานหลักแล้ว ผู้รับผิดชอบโครงการคนเดียวทำขั้น Requirement gathering ได้ครบ ไม่มีขั้นอนุมัติ จึงเขียนสิ่งที่ยังไม่ชัดเป็นสมมติฐานที่ตรวจได้แทนการรอคำตอบ

Checklist ก่อนส่งแผน: ทุกหน้าจอมีผู้ใช้และสิทธิ์, ทุกข้อมูลส่วนบุคคลมีเหตุผลที่เก็บ, ไม่มีการเรียกผู้ให้บริการ AI โดยตรง, ทุกคำถามที่เปลี่ยนขอบเขตอยู่ในหัวข้อคำถามที่ต้องยืนยัน

ข้อผิดพลาดที่ต้องเลี่ยง: ใช้ AI กับขั้นตอนที่เป็นกฎตายตัว, เขียน Spec ที่ต้องการคำตอบ AI แบบตรงตัว, ลืมคิวเจ้าหน้าที่สำหรับรายการความมั่นใจต่ำ

## งานข้อเสนอสำหรับทีม presales

เมื่อผู้ใช้เป็นทีม presales หรือขอเอกสาร "Proposal ฝ่ายขาย 14 หัวข้อ" หรือ "Executive Summary 2 หน้า" ในเมนูงานเอกสาร ให้ใช้ skill `doc-presales-proposal` (คู่มือการเขียน Proposal ของทีม presales) ร่วมกับเอกสารของขั้นนี้
- Intent และ Spec คือวัตถุดิบของหัวข้อ 04 Our Understanding และ 05 Proposed Solution: เป้าหมายของลูกค้าเป็น Ambition, ปัญหาเป็น Gaps, เกณฑ์ยอมรับและ REQ-ID เป็นตัวผูกหน้า feature
- Plan คือวัตถุดิบของหัวข้อ 06 Our Approach และ 08 Timeline ชื่อ phase และจำนวนเดือนต้องเป็นชุดเดียวกับที่จะใช้ในหัวข้อ 01 และ 12
- ทุก gap ที่เขียนในหัวข้อ 04 ต้องมีหน้าที่ตอบในหัวข้อ 05 ถ้า Spec ยังไม่มี feature ที่ตอบ gap ใด ให้ถามในคำถามที่ต้องยืนยัน แทนการเขียนหน้า solution ลอย ๆ
- ตัวเลขของลูกค้าและของบริษัทต้องมีแหล่งที่มา ที่ยังไม่มีให้ถามในขั้น Grill-me ของเอกสาร ห้ามแต่ง
- เขียน Executive Summary หลังสุด แล้วกด "ตรวจ QA ทั้ง deck" ก่อนส่ง
- ชื่อแพลตฟอร์มคือ Prompt Serve ตามด้วยประโยชน์เชิงธุรกิจเสมอ และใช้ชื่อในเอกสารลูกค้าตามกติกาการตั้งชื่อของบริษัท
